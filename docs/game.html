Game Session & Controller Lua

Wiring a live game session to the table screen, locally or over the network.
On this page

How a game actually runs, end to end

Of the four files on this page, two — session.lua and host_engine.lua — belong to the platform-agnostic engine described on core.html: they're copied verbatim into server/engine/src/game/ and can run either inside the LÖVE client (LuaJIT) or inside the dedicated Go server (gopher-lua). The other two, controller.lua and sound.lua, are client-only — controller.lua has no love.* calls itself, but it's only ever instantiated by client-side screen code, never by the server.

There are three distinct ways a game ends up running, and the same engine files play different roles in each:

ModeWhere Session livesWhere host_engine.lua runsWhat the table talks to
Local practice (practice_game.lua, solo/hot-seat) In the LÖVE client process, one Session shared by every seat. Not used at all — there's no network, so there's nothing to broadcast or filter. controller.Host, calling the session directly in-process. Session:setActiveSeat lets the UI "act as" whichever seat's avatar was clicked (CONTROLS.md: "Click a player's avatar: practice games act as that seat").
Direct host/join (host_server.lua / game_client.lua, ad-hoc LAN/Discord-invite game) In the LÖVE process of whichever player is hosting. In the host's own LÖVE process, wired to that player's host_server.lua connection object. Host player: controller.Host (direct, no network hop for the host's own actions). Every other player: controller.Client, which turns every table action into a request* message sent over the network protocol to the host.
Dedicated server game (room.lua, via the Go lobby server) Inside the Go server process, running under gopher-lua. Also inside the Go server process, under gopher-lua — see server/internal/engine/engine.go on server.html for exactly how Go drives this Lua object. Every connected player, host included, is a controller.Client talking to the server over server_client.lua — nobody's local client holds the authoritative Session at all.

In every mode the shape above host_engine/controller is the same: a mouse action on the table screen calls a method on whatever controller object the table was constructed with. A Host controller validates ownership itself and calls straight into Session; a Client controller just serializes the call into a JSON request message and sends it off, trusting the remote host engine to validate and apply it, then relies on the next broadcasted fullState (filtered per-recipient by state_filter.lua) to reflect the result back. This is why Session and table_actions.lua only need to exist once per authoritative copy of the game, never once per player.

session.lua — the authoritative game state

src/game/session.lua
Port of lib/game/game_session.dart. Owns the single authoritative TableState for a running game, wraps every table_actions.lua call with a human-readable game-log entry, and notifies listeners whenever anything changes. Mirrored to the server

Session is a plain Lua metatable-based "class" (Session.__index = Session). Time is injected: opts.now defaults to love.timer.getTime, but can be overridden (tests, or the gopher-lua server where there's no love global at all) — it drives both the game-log's elapsed clock and the arrow-preview lifetime timer. Session:update() must be called once per frame/tick to fire any due timers.

Construction

Session.new(opts) -> Session
opts: {game, localPlayerId, initialState, isLocalPractice, clockStart, now}. Builds a definitionsById index over opts.game.cards up front (first-id-wins on duplicates) for fast card-title/metadata lookups. activeSeatId starts nil; listeners and timers start empty; cardDragPreviews/arrowDragPreviews (keyed by player id) hold other players' cosmetic drag previews, relayed by host_engine.lua.
Session.dealFromZones(opts) -> Session
The main constructor for a fresh game. opts: {game, players, localPlayerId, deckConfigsByPlayerId, sharedDeckConfigsByZoneId, isLocalPractice, now, rng}. Builds the initial deal:
  • If any shared zone has standardDeck = true, synthesizes a full 52-card deck via models.buildStandardDeckCards() and merges its definitions in alongside the game's own.
  • For each player, for each of their non-shared "card"-kind zones: if the zone dealsBuiltDeck, pulls entries from that player's chosen DeckConfig (or — if no deck configs were supplied at all, e.g. a quick practice game — from "one of everything" via DeckConfig.full-style fullDeckEntries); otherwise uses the zone's own fixed entries. Cards are instantiated with fresh UUIDs, shuffled first if zone.autoShuffle.
  • For each player's non-shared "widget"-kind zones, deals a docked simpleCounter widget seeded from the zone's counter defaults.
  • For shared zones: the standard deck's entries, a loaded shared deck config, the zone's fixed entries (if any, or if it's a discard pile), or — failing all of those — one of everything, in that priority order.
Returns a freshly-constructed Session wrapping the dealt TableState at revision = 0.
Session.localPractice(opts) -> Session
Thin wrapper over dealFromZones that sets localPlayerId = opts.players[1].id and isLocalPractice = true — used by practice_game.lua.

Lookups & visibility

Session:actingPlayerId() -> id
Returns activeSeatId if set (practice mode's "act as this seat"), else localPlayerId.
Session:setActiveSeat(playerId)
Only takes effect when isLocalPractice is true — clicking an avatar in a networked game has no such effect.
Session:findCard(id) / findWidget(id) / definition(definitionId) / playerName(playerId)
Straightforward lookups via the model's own id-lookup helpers and the cached definitionsById.
Session:zoneDefinition(zoneId) -> ZoneDefinition
Unwraps a synthetic deck-widget zone id (deck_widget_zones.parse) to find the real ZoneDefinition underneath; throws if the resolved id isn't a real zone — the one place in this file that errors rather than failing silently.
Session:isPubliclyVisible(card) -> boolean
A card is visible to everyone only if it's face up and either it's on the table, or it's unowned, or it's in a zone marked visibleToAll (never true for a hand or a deck-widget zone). Used to decide whether a card's title can safely appear in the game log.
Session:titleOf(card) / revealedCardName(oldCard, newCard)
revealedCardName only returns a name if the card was publicly visible before or after the change — this is how the log can say "played a card to the table" for something that was secret until just now versus naming it outright when it was already public.

Logging

Session:elapsedMs() -> integer
max(0, floor((now() - clockStart) * 1000)).
Session:log(actingPlayerId, action)
Appends a new LogEntry ("<player name> <action>") directly onto self.state.log via util.copyWith — note this bypasses table_actions.lua entirely and does not bump the revision by itself; logging always happens alongside a real state-changing call that bumps the revision on its own.
Session:logPlayedToTable(actingPlayerId, oldCard, instanceId)
Shared helper behind the "played <card> to the table from hand/the <zone>." log lines used by several of the card operations below.

Card operations

Each of these calls the matching pure function in table_actions.lua, assigns the result back to self.state, appends a game-log entry describing what happened (using the pre-change card to decide what's nameable), and calls self:notify().

Packs & the card library

Session:generatePack(setId, actingPlayerId, rng)
Looks up the GameSet and its cards, delegates the actual selection to pack_generator.selectPackCards, deals the result straight into the acting player's hand face-up, and logs "generated a pack from the <set> set."
Session:createCardFromLibrary(definitionId, x, y, actingPlayerId)
Deals one fresh instance of an existing card definition onto the table (not the hand) at the given point — the in-game Card Library's "place a card" action. No-ops silently if the definition id isn't known. Logs 'created "Name" from the card library.'

Networking hooks

Session:applyRemoteState(newState)
Client-side: adopts newState only if its revision is strictly greater than the current one (guards against out-of-order delivery), then notifies listeners. This is the one place a Session running as a client (not authoritative) ever changes state, bypassing table_actions entirely since the state already arrived pre-computed from the host.
Session:syncConnectedPlayerIds(connectedNonHostIds)
Host-side: given a set of currently-connected non-host player ids, updates every player's connected flag (the host itself is always considered connected), logging "connected."/"disconnected." for whoever changed state, and bumps the revision directly (bypassing table_actions, since connection state isn't really a table action). Called from host_engine:onRoster.

host_engine.lua — the host's authoritative loop

src/game/host_engine.lua
Port of lib/game/host_game_engine.dart. The glue between a raw network connection object (anything implementing the small server interface below) and a Session: applies incoming client requests as that connection's player (with ownership checks of its own, independent of Session's), broadcasts a per-recipient-filtered full state once per revision change, and relays cosmetic drag/arrow previews between clients. Mirrored to the server

E.new(session, server, hostPlayerId) takes any server object exposing onIncoming, onRoster, reclaimableIdCheck (settable callback fields), plus roster(), sendTo(id, type, payload) and broadcast(type, payload, exceptId). In the direct host/join mode that's host_server.lua; inside the Go server it's whatever Go-side object server/internal/engine/engine.go exposes to the embedded Lua state (see server.html).

Lifecycle

E:start()
Subscribes to the session (self.session:addListener(function() self:broadcast() end) — every state change triggers an attempted broadcast), wires its own handleMessage/onRoster into the server's callback fields, installs a reclaimableIdCheck (lets a disconnected player's id be reclaimed by a reconnecting client — true only if that id belongs to a currently-disconnected player), seeds previouslyConnected from the server's current roster, and does an initial broadcast.
E:dispose()
Unsubscribes the listener and clears all three callback fields on the server object.
E:onRoster(roster)
Called whenever the underlying connection's player roster changes. Any newly-connected non-host player is sent a one-time "gameData" message (the full GameDefinition, JSON-encoded) so they have the card/zone definitions before any state arrives. Any player who just disconnected has their drag/arrow previews cleared (so a frozen "ghost" preview doesn't linger for everyone else). Finally calls Session:syncConnectedPlayerIds to update connection flags and log the join/leave.
E:broadcast()
No-ops if state.revision hasn't advanced since the last broadcast (lastBroadcastRevision). Otherwise computes the set of visibleToAll zone ids once, then sends every non-host player their own "fullState" message — the state run through state_filter.filterForRecipient for that specific player. The host never gets this message because the host's own client already holds (or in the dedicated-server case, is literally running inside the same process as) the unfiltered Session.

Permission checks

These mirror (and are independent of) Session:canStackOnto/isOwnedOrUnowned on the client side — the host engine never trusts a client's own claim about what it's allowed to do.

MethodReturns true when...
E:zoneOwnerId(zoneId, requester)For a deck-widget zone, the owner of the widget it belongs to; for a real zone, nil if shared, else the requester themself.
E:allowedDeckWidgetZone(zoneId, requester)True for any non-deck-widget zone id; for a deck-widget zone, only if the requester owns that widget.
E:allowedCard(id, requester)The card exists and is either unowned or owned by the requester.
E:movableWidget(id, requester)Widget doesn't exist (trivially movable — the id might be about to be created) OR it's not docked in a zone AND it's unowned or owned by the requester.
E:allowedWidget(id, requester)Widget exists and is unowned or owned by the requester (no docked-zone exception, unlike movableWidget).
E:allowedDelete(id, requester)Widget exists, passes movableWidget, and has no creatorId or the requester is that creator.
E:allowedDrawOrShuffle(rootId, requester)Every card in the resolved pile is unowned or owned by the requester.

Incoming request messages

E:handleMessage(clientId, msg)
The dispatch table at the heart of the networked protocol: a big if/elseif chain on msg.type, wrapped in pcall so a malformed or malicious message from one client can never crash the host (errors are swallowed with a print log line, not propagated). Every branch validates permissions first via the table above, then calls straight into the matching Session method, always passing clientId as the acting player — a client can never act as anyone but itself. Drag previews (DragPreviewSink)

Separate from the authoritative TableState entirely: while a player is mid-drag, other players should see the card/arrow moving smoothly in real time without that generating a flood of real, revision-bumping state mutations. These messages are purely cosmetic and never touch table_actions.lua.

E:publishCardDragPreview(playerId, ids, fx, fy)
No-ops if either fractional coordinate is missing. Stores the preview on session.cardDragPreviews[playerId] and re-broadcasts it to everyone except the host player (E:exceptFor) via the raw server:broadcast — bypassing per-recipient state filtering, since drag previews aren't subject to the same hidden-information rules as real state (a card id already known to be in play is simply shown moving).
E:clearCardDragPreview(playerId)
Removes the stored preview and broadcasts a cardDragPreviewEnd, but only if one was actually set (avoids spamming no-op end messages).
E:publishArrowDragPreview / clearArrowDragPreview
Same pattern for the Tab+drag arrow-draw preview from CONTROLS.md.

On the client side, cardDragPreview/arrowDragPreview messages are sent by controller.Client's previewCardDrag/previewArrowDrag and are consumed by whatever renders remote cursors on the table screen (not covered by this file — this file only relays them).

controller.lua — what the table UI talks to

src/game/controller.lua
Port of lib/game/table_controller.dart. Defines the single interface the table screen is written against: two implementations, M.Host and M.Client, with identical method sets, so the table code never needs to know or care which mode it's running in.
Every public method on both Host and Client has the same name and argument order — this is the whole point of the abstraction. The table screen is constructed with some controller object and simply calls, say, controller:moveCard(id, x, y) without an if isHost then ... else ... end anywhere in its own code.

Host (M.Host)

Host.new(session, previewSink) — previewSink is optional and, when present, is the host_engine instance itself (anything exposing publishCardDragPreview/clearCardDragPreview/publishArrowDragPreview/clearArrowDragPreview).

Host:acting() -> id
Delegates to session:actingPlayerId() — respects practice mode's active-seat override.
Host:isOwnedOrUnowned(instanceId) / isOwnedOrUnownedStack(rootId) -> boolean
Client-side mirrors of the same ownership logic host_engine enforces authoritatively — in local/host-authoritative modes there's no separate network hop to reject an action on, so these checks have to happen right here before calling into Session at all.
Host:zoneOwnerId(zoneId) -> id|nil
Same resolution logic as host_engine:zoneOwnerId (deck-widget unwrap, shared-zone check, else the acting player), duplicated here rather than shared because this runs client-side against the local Session directly.

Every other Host method (moveCard, moveGroup, moveStack, rotateStack, bringToFront, flipCard, giveCard, stackCard, moveToHand, reorderHand, drawCard, shufflePile, drawFromZone, returnToZone, shuffleZone, loadDeckIntoZone, startSearchZone, startSearchPile, stopSearch, createWidget, createArrow, moveWidget, setWidgetValue, deleteWidget, setWidgetColors, duplicateWidget, attachWidgetToCard, generatePack, createCardFromLibrary) follows the same shape: optionally gate on one of the two ownership checks above, then call the matching self.session:<method>(..., self:acting()).

Host:previewCardDrag(primaryId, passengerRootIds, fx, fy) / endCardDragPreview() / previewArrowDrag(fx, fy, fx2, fy2) / endArrowDragPreview()
Forward straight to previewSink if one was supplied (no-op otherwise — practice mode has no preview sink since there's nobody else to show a preview to).

Client (M.Client)

Client.new(send) — send(type, payloadObject) is the only dependency; in practice it's a thin wrapper that hands the message off to server_client.lua or game_client.lua for actual transmission.

Every method builds the matching request payload (a json.object(...) literal with exactly the keys host_engine's dispatch table expects) and calls self.send(type, payload) — there is no local validation or optimistic update at all; the client simply fires the request and waits for the next fullState broadcast to reflect whatever the host actually did (or silently refused). This keeps the client dumb and the host/server the single source of truth. The method-name-to-message-type mapping exactly matches the table in host_engine.lua above (e.g. Client:moveCard sends "requestMove", Client:giveCard sends "requestGiveCard" with newOwnerId coerced to json.null when nil since JSON has no bare "undefined").

Client:previewCardDrag / endCardDragPreview / previewArrowDrag / endArrowDragPreview
Send the cardDragPreview/cardDragPreviewEnd/arrowDragPreview/arrowDragPreviewEnd messages described under host_engine's preview relay above.

sound.lua — fire-and-forget sound effects

src/game/sound.lua
Port of lib/game/sound_service.dart. Client-only; plays short effect clips with up to 4 overlapping voices per effect so rapid repeated actions (several quick card draws) don't cut each other off.
Effect keyFile
drawassets/audio/draw.wav
playCardassets/audio/playcard.wav
shuffleassets/audio/shuffle.wav
tapassets/audio/tap.wav
untapassets/audio/untap.wav
errorassets/audio/error.wav
S.play(effect) -> boolean
On first use of a given effect key, loads a love.audio.newSource(path, "static") and clones it 3 more times into a 4-voice pool (VOICES = 4), cached in the module-local pools table keyed by effect name. Each call takes the next voice round-robin (pool.next wraps mod 4), stops it if it's still playing from a previous trigger, and restarts it — this is what lets the same effect overlap itself up to 4 times without an unbounded number of sources. The whole body runs inside a pcall, and the function returns false (or the pcall's own ok flag) on any failure rather than throwing — deliberately silent, per the file's header comment, so a missing/corrupt audio asset never crashes gameplay. Also no-ops immediately if love.audio isn't available at all (test mode disables the audio module, see conf.lua).
